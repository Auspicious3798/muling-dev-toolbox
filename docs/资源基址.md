# 资源基址（开源部署说明）

沐柠环境盒的所有工具包都放在阿里云 OSS 上，配置写在 `config/downloads.json`。
开源后，**别人 fork 这份代码不应该继续消耗官方桶的流量**，所以资源基址是可覆盖的。

## 三种指定方式

优先级从高到低：

| 方式 | 写法 | 适用场景 |
|---|---|---|
| 环境变量 | `MULING_ASSET_BASE=https://cdn.example.com/muling` | CI、临时测试、命令行启动 |
| 配置文件 | `config/downloads.json` 顶层 `"assetBase": "https://cdn.example.com/muling"` | 自己打包的定制版 |
| 不指定 | 走默认官方桶 | 官方发行版 |

## 生效规则

代码在 `electron/utils/assetBase.cjs`，只在内存里改写，**不会改动磁盘上的配置文件**：

- 绝对地址且以官方桶开头 → 替换掉前缀，接到你的基址上
  `https://<官方桶>/jdk/jdk-21.zip` → `https://cdn.example.com/muling/jdk/jdk-21.zip`
- 以 `/` 开头的相对路径（如检查更新用的 `/version.json`）→ 拼到你指定的基址上
- 其它地址原样返回

也就是说：只要你把自己那 75 个包按同样的目录结构放好（`/<tool>/<file>`），
配置一个字都不用改，换基址就能整体换源。

<基址>/version.json                  # 检查更新用（可选）

完整的文件清单见 `docs/OSS-资源清单.md`。

## 自建源的注意事项

1. **必须是直链**：服务端不要返回 302 到需要登录的地址，也不要包一层网页。
2. **支持 Range 请求**：下载器用了断点续传（206），不支持会退化成整包重下。
3. **不要开防盗链**：桌面客户端请求没有 Referer，白名单一开自己都下不了。
4. **建议关闭 ListObjects**：公共读要开，但不要让人能列出目录。

## 官方桶的安全实践

- 仓库里**不含任何 AccessKey**，只有公开可读的下载直链。
- 上传用的 AK 只放本机环境变量，不进仓库、不进 CI 日志。
- 如果以后要做私有资源（用户备份、日志），走服务端签名 URL，客户端只拿短时链接。
