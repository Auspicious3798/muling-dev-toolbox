# 代码签名

> 目的：让 Windows 认出安装包是「Auspicious3798 发布的」，减少 SmartScreen 拦截和杀毒软件误报。

## 一、为什么必须签

未签名的 exe 会有三种后果：

1. **SmartScreen 首启拦截**——用户看到「Windows 已保护你的电脑」，需要点「更多信息 → 仍要运行」。大量用户到这一步就跑了。
2. **杀毒误报**——沐柠会写 `HKCU` 环境变量、拉起 `mysqld.exe`/`nginx.exe`、监听端口，这些行为和恶意软件的「持久化 + 起服务」高度重合，未签名时更容易被启发式规则命中。
3. **无法追溯**——出了事用户不知道是谁发布的，也没法验证包没被篡改。

签名解决的是 1 和 3，对 2 有显著缓解但不是万能（声誉要靠时间积累）。

## 二、买什么证书

| 类型 | 价格区间 | 特点 | 适不适合 |
|---|---|---|---|
| **OV（组织验证）** | ￥1500~3000/年 | 需要营业执照，个人开发者可用个人身份申请部分颁发机构 | ✅ 推荐起步 |
| **EV（扩展验证）** | ￥4000~8000/年 | 走硬件 UKey，**有 SmartScreen 即时信任**，不用养声誉 | ✅ 预算允许就上 |
| **Azure Trusted Signing** | $9.9/月 | 微软云签名服务，个人也可申请（需身份验证），免 UKey | ✅ 性价比最高 |
| 自签名证书 | 免费 | 只能本机联调，用户侧仍然警告 | ❌ 不能对外发 |

**个人开发者的现实选择**：预算紧就 Azure Trusted Signing（每月 10 美元，签出来的证书照样被 Windows 认可）；想省事就 OV。

## 三、接进来（三条路，任选一条）

electron-builder 认下面三种输入，优先级从高到低。

### 路线 A：环境变量 + pfx（最通用）

从 CA 拿到证书后，导出成 `.pfx`（带密码），然后：

```powershell
$env:CSC_LINK = "E:\certs\auspicious3798.pfx"     # 也支持 base64 字符串
$env:CSC_KEY_PASSWORD = "你的pfx密码"
npm run electron:build
```

electron-builder 会自动调用 signtool 签名，**不用改任何配置**。

### 路线 B：证书装进系统证书库 + 按主题名匹配

EV 证书通常只能装进 UKey/证书库，导不出 pfx。这时把 `package.json` 里的 `build.win.publisherName` 改成证书主体名（当前是 `Auspicious3798`），electron-builder 会自动从证书库找匹配的证书：

```jsonc
"win": {
  "publisherName": "你的证书主体名"   // 必须和证书 Subject 里的 CN 完全一致
}
```

### 路线 C：Azure Trusted Signing

装 `@electron/azure-trusted-signing`，在 `package.json` 里配 `win.azureSignOptions`，凭据走环境变量。这条路线最省心但要先开通 Azure 服务。

## 四、时间戳（很重要）

**一定要带时间戳**，否则证书过期后，之前签的所有包都会变成「签名无效」。

electron-builder 默认会去时间戳服务器打时间戳。如果想显式指定：

```jsonc
"win": {
  "rfc3161TimeStampServer": "http://timestamp.digicert.com",
  "timeStampServer": "http://timestamp.sectigo.com"
}
```

本次没有写进 `package.json`，因为默认值已经够用，写死反而在服务器临时不可用时阻塞构建。

## 五、验证签名是否生效

```powershell
pwsh -File scripts/verify-signature.ps1
```

输出示例：

```
文件：沐柠环境盒-Setup-v1.0.0.exe
  大小：96.3 MB
  状态：Valid
  签名者：CN=Auspicious3798, O=Auspicious3798, ...
  颁发者：CN=DigiCert Trusted G4 Code Signing RSA4096 SHA384 2021 CA1
  有效期：2026-11-13 ~ 2027-11-13
  时间戳：已加盖
```

`状态：Valid` 且 `签名者` 不为空，才算成功。

## 六、没买证书时怎么联调

用自签名证书把流程跑通（**不能对外发**，用户侧依旧警告）：

```powershell
pwsh -File scripts/make-dev-cert.ps1
```

它会生成 `build/certs/dev-signing.pfx`，把证书装进「当前用户 → 受信任的根证书颁发机构」，并对最新的 Setup.exe 签名。之后用 `CSC_LINK` 指向这个 pfx 就能走完整构建流程。

> 注意：自签名证书装进「受信任的根」只对本机有效。发给别人，人家机器上没有这个根证书，签名依旧显示「未知发布者」。

## 七、发布前的检查清单

- [ ] 证书有效期覆盖发布时间
- [ ] `publisherName` 与证书 Subject 一致
- [ ] 时间戳已加盖（`verify-signature.ps1` 显示「已加盖」）
- [ ] `scripts/verify-signature.ps1` 全部 `Valid`
- [ ] 在**干净虚拟机**里双击安装包，确认不再弹 SmartScreen（EV 立刻生效，OV 需要累积下载量）

## 八、声誉说明

OV 证书签出的包，SmartScreen 仍然可能警告——微软的声誉系统按「该证书的下载量 + 举报数」计算，新证书相当于从零开始。

- **EV 证书 / Azure Trusted Signing**：立刻获得信任，不弹警告
- **OV 证书**：需要几百到几千次「干净下载」才会转正，期间可以引导用户点「仍要运行」

这不是 bug，是微软的策略。想彻底避免就上 EV 或 Trusted Signing。
